# 来源、审核与版本边界

## 素材记录

| 素材 | 最低记录 |
| --- | --- |
| 生成图 | 实际提示词、工具/可见参数、参考文件和职责、输入/输出哈希、像素、可见问题与选择结果 |
| 修改/排版图 | 原素材记录、改变内容、处理工具、输出哈希；精确文字单独保留 |
| 照片/视频/截图 | 对象、来源页、作者、许可或授权依据、适用范围、取得日期、原文件哈希、使用理由 |
| 配音 | 干净稿、实际请求稿、声音/模型/语速、请求指纹、实测时长/时间戳、听审状态 |
| 音乐/字体 | 实际文件、来源、许可、署名要求与文件哈希 |

引用 URL 证明来源路径，不自动证明可再利用。公开可见也不等于公共领域。对有实质版权限制的素材，使用明确许可、用户自有材料或重新制作的说明性图形。不要把生成图登记成真实档案或实际产品截图。

## 三类审核

**内容与分镜反审：** 原稿是否完整覆盖；科学/历史暗示是否准确；方法是否帮助理解；IP、重复、时长和能力风险是否有退路。

**语音导演审核：** 实际请求稿与原文、参数一致，节奏自然，语法受支持，易错读音有处理。未生成的音频不能声称听过。

**成片审核：** 对最终文件做技术检查、实际视觉检查以及可执行的试听/播放。每项注明执行方式和对象哈希。人类接受是另一个状态，不由脚本赋值。

审查输入包括文稿、计划、提示词、资产规格及相关配置。计划/素材/字体/布局/时间线或渲染逻辑改变后，重做受影响审查并保存新证据。不要为了通过检查重写历史哈希或伪造 Reviewer。

## 可复现到什么程度

快照与哈希能证明用了哪些文件，以及本地渲染输入是否改变。它们不能保证闭源生成服务未来返回同样的图片或声音。保存已选素材与实际音频比只保存提示词更有恢复价值。

仓库公开模板、代码与独立示例；实际客户项目宜放私有仓库或私有素材存储。大媒体可以外置，但恢复清单必须指出必需文件、哈希、取得方式和权限，不能把一个空目录描述成完整备份。

## 并行与版本

每期一个目录；同一期只安排一个写入者。并行 Agent 在独立目录制作，审查 Agent 默认只读。共享规则、默认声音和品牌参考由维护任务更新，生产任务使用已冻结的副本。

将反馈归为：本期内容问题、品牌默认问题、运行时缺陷或个人偏好。只把有证据且可泛化的结论提升为共用规则，避免每次偶发问题都变成永久限制。版本记录写触发问题、改变行为、验证方式和已知局限。

## 验收记录应回答

“检查了哪个文件，用什么方法，观察到什么，哪些没有检查？”

例如“完整解码通过，检查了所有字幕与转场静帧，未实际听完整片，听感待验收”比“全部通过”更可用。用户要求不播放时，遵守该边界并完成允许的离线检查。
